# 发布门、首页游标与历史导出的真实性

## 发布前重新检查（dependency report）

点"发布"不会直接渲染，而是先按确定的 `as_of`（默认当天，也可显式传入）跑全量报告：

* 素材存在、scope 与镜头声明一致（公共不能标私有）；
* 不是 thumbnail-only；授权未撤回且在有效期内；外部来源未失效；
* 引用模式有新版提示（warning），复制模式核对本地 blob；
* 规则卡片绑定的版本在 `as_of` 有效且为最新生效版本（否则 error）；
* 设施/窗景记录在 `as_of` 处于有效窗口；推荐卡片有 `source_ref`；
* 每个选中渠道做安全区检查。

**error 阻断入队**（HTTP 422 附完整 issues）；warning 可发布但会回传提醒。
工作器 claim 后按同一 `as_of` 复检，避免排队窗口里依赖变坏。

## 首页游标引用项目版本

* 保存或成功恢复时游标前移到对应版本；首页只显示游标版本号。
* 越权访问/非成员不进列表（INNER JOIN 成员表），非成员直接 resume → 403。
* 旧版本可通过项目版本接口回看；新编辑总是从最新版本 fork，但游标保证"离开时看到的版本"
  可随时找回。

## 旧导出保留制作时的真实信息

导出行 `exports` 写入后不再有任何更新路径：

* `snapshot_json` 复制（非引用）规则原文、房型名、素材标题、空间标签、卡片绑定与推荐来源；
* `checks_json` 保存发布时的检查结果（含 as_of）；
* 产出文件写到 `storage/output/export_{id}/{channel}.*`（SRT/CSV/SVG/可选 MP4）。
  路径稳定、只读。

因此：

| 之后发生的事 | 旧导出表现 |
|---|---|
| 房型描述/入住规则被修改 | 旧导出快照不变，镜头清单与字幕不变 |
| 母素材重新上传新版本 | 旧导出仍指向/保留 v1 sha256 |
| 授权撤回 | 已生成导出保留（下架是运营动作），新发布阻断 |
| 同事又编辑了几个版本 | 旧导出的 project_version_id 不变 |
| 想加"附近推荐" | 旧导出不会自动出现；新建时间线且必须填依据来源 |
| 外部图床挂了 | 引用版新发布阻断；复制版因本地有 blob 可继续内部复现 |

用例：`test_home_cursor_pins_exact_version_and_old_export_frozen`（规则从 14:00 改到
16:00 后，旧导出里仍冻结为 14:00）。

## 工作器产出说明

| 文件 | 内容 |
|---|---|
| `{channel}.srt` | 按镜头累计时长（start/end）与 `caption` 生成的标准 SRT |
| `{channel}_shots.csv` | 序号/镜头 id/作用域/房型/空间/素材版本/引用或复制/时间区间/内嵌提示/安全区标记 |
| `{channel}_contact.svg` | 逐镜头带渠道安全区 guides 的接触印片（内嵌提示红绿框） |
| `{channel}_storyboard.svg` | 故事板（ffmpeg 缺失时的预览降级方案） |
| `{channel}_preview.mp4` | 仅当系统有 ffmpeg 且素材为完整复制视频时生成 |

Web 的 `/output.html?eid=` 页面展示产出并完整呈现冻结快照 JSON。
